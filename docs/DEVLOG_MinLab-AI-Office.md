## MinLab AI Office
2026-10-29
v0.1 ~ v0.2.7

### 2D 도트 사무실과 승인 단계(A·E·B·C)를 갖춘 첫 공개

**작업 내용**

**작업 목적**
여러 AI(ChatGPT·Claude·Codex·Gemini·Grok)에게 일을 나눠 맡기고 진행 상황을 2D 도트 사무실로 보는 개인 AI 개발팀 사무실을 만듦. 사람이 승인해야 다음 단계로 넘어가는 흐름을 세움.

**주요 변경**
- React + Vite + TypeScript 앱과 Supabase(로그인·DB·서버 함수)로 첫 버전을 만들고, 캐릭터(미니엉·Studio A·Studio B 등)를 도트 그림으로 그림.
- 기획 승인(A)·실행 승인(E)·올리기 승인(B)·배포 승인(C) 단계를 DB 규칙과 앱 규칙으로 똑같이 막음.
- Claude PM이 기획서를 받아 작업을 나누고 담당을 정하는 계획을 만들게 하고, Codex는 지시서를 넘기는 방식으로 연결함.
- 요청 자료·결과 스크린샷 이미지 첨부(비공개 저장소), 링크 읽기(내부망 차단), 확인 질문·답변 기록을 추가함.
- 묻기·요청 입력창, 새 프로젝트 GitHub 저장소 만들기 버튼, 프로젝트 수정 기능을 추가함.
- 운영 배포는 release 브랜치만(Cloudflare Pages), 이 저장소는 시험 통과 시 PR·병합까지 자동으로 하도록 작업 규칙을 정함.

**작업 이유**
요청부터 결과 확인까지 여러 AI 창을 오가며 복사·붙여넣기 하던 일을 한곳에서 관리하고, 각 AI의 사용량을 아끼기 위해 시작함. 검증하지 않은 자동 실행을 성공으로 보이지 않게 승인 단계를 먼저 세움.

**확인 결과**
타입 검사·단위 시험·빌드와 DB 규칙 시험이 통과함. Claude PM 경로를 운영에서 실제로 실행해 계획이 돌아오는 것을 확인함. 링크 읽기와 Storage 업로드를 실측함. 개발 도구 취약점(npm audit) 0건.

**다음 작업**
AI를 안 써도 되는 일은 규칙으로 처리하고, Gemini 무료로 이미지·질문을 처리하는 길을 붙일 필요가 있음.

## MinLab AI Office
2026-10-30
v0.2.8 ~ v0.4.2

### Gemini 무료 기획서 초안과 견본 먼저 흐름, 개발일지

**작업 내용**

**작업 목적**
토큰을 아끼려고 싼 길부터 쓰는 흐름(규칙 → Gemini 무료 → 구독 수동 → 구독 자동)을 만들고, 요청부터 결과까지 휴대폰만으로 진행되게 함.

**주요 변경**
- Gemini 이미지 분석·문서 요약(PDF·DOCX·XLSX·PPTX·ZIP 등)과 앱 안 미리보기를 추가함. 기본 모델을 gemini-3.5-flash-lite로 바꿈.
- 접수 확인하면 Gemini가 기획서 초안을 자동으로 쓰고, 기획 승인(A)하면 Claude PM에 자동 전송함. PM 계획은 1회용 제출표로 앱에 자동 저장됨.
- 견본 먼저(Prototype First): 화면이 새로운 일은 견본을 먼저 보고 승인(P)한 뒤 개발하게 함.
- Claude 보조 개발을 두 번째 루틴으로 자동 시작하고, 여러 기기에서 실시간으로 반영되게 함(Supabase Realtime).
- AI별 동시 작업 상한, PR CI 결과 자동 확인, 배포 승인 시 서버가 release를 앞당기는 흐름을 추가함.
- 대화를 계정에 저장해 기기 간에 이어 보고, 프로젝트·날짜별 개발일지(Markdown)를 만듦. 입력창 매니저 이름을 미니엉으로 정함.

<details><summary>세부 정보 (작업 이유, 확인 결과, 다음 작업)</summary>

**작업 이유**
소유자가 정한 목표("사용자는 질문·승인·결과 검토만")에 맞춰 손으로 옮기던 단계를 무료·구독 안에서 하나씩 자동으로 바꿈. Codex 자동 실행은 공식 무인 인증이 없어 Linear 절충안으로 결정만 기록함.

**확인 결과**
Gemini 일반 질문·이미지 분석을 운영에서 실측함(2.5 모델은 새 사용자 404라 3.5로 교체). 시험·빌드·DB 시험이 모두 통과함. Codex 서버 자동 시작은 미검증으로 남김.

**다음 작업**
사무실 화면에서 지금 내가 할 일이 바로 보이게 하고, 휴대폰 알림을 붙일 필요가 있음.
</details>

v0.4.3 ~ v0.4.22

### 휴대폰 알림·내 차례 목록과 승인 후 자동 진행

**작업 내용**

**작업 목적**
휴대폰에서 알림을 받고, 내가 손댈 일만 모아 보고 바로 승인할 수 있게 함. 승인 뒤의 일(개발 시작·PR·배포)은 자동으로 이어지게 함.

**주요 변경**
- 실행 승인 = Claude 개발 시작, 올리기 승인 = 승인된 diff 그대로 PR, 배포 승인 = 병합 후 release 앞당기기로 연결함.
- Claude 보조 개발 결과를 세션이 직접 앱에 보내 결과 패키지로 저장함.
- 사무실 말풍선을 단계 표시(기획? 결과? 배포? 막힘!)로 바꾸고, 업무 탭 맨 위에 "내 차례" 목록과 멈춤 자동 감지를 추가함.
- 휴대폰 웹 푸시 알림과 홈 화면 앱 아이콘(미니엉 얼굴)을 추가함. 휴대폰에서 누르는 운영 배포 버튼(GitHub Actions)을 만듦.
- Gemini 견본 자동 생성, 사진 자동 분석, Gemini 답 조각조각 바로 보여 주기를 추가함.
- 대화 탭을 분리하고 업무 카드를 한 줄로 접게 하는 등 휴대폰 화면을 정리함. 흐름 시뮬레이션 시험으로 찾은 꼬임을 고침.

<details><summary>세부 정보 (작업 이유, 확인 결과, 다음 작업)</summary>

**작업 이유**
소유자가 주로 아이폰 홈 화면 앱으로 쓰기 때문에 PC 없이 알림 → 확인 → 승인이 되어야 했음. iOS 사파리 입력창 빈칸 등 휴대폰에서만 보이는 문제도 함께 고침.

**확인 결과**
시뮬레이션 시험(요청~배포 흐름)과 단위·DB 시험이 통과함. 웹 푸시는 운영에서 시험 알림으로 확인함. 데스크톱 1400px·휴대폰 400px 스크린샷에서 콘솔 오류·가로 넘침 없음.

**다음 작업**
AI별 휴가(쉬게 하기)와 대화창에서 여러 질문·업무를 한 번에 처리하는 기능이 필요함.

### AI 휴가·팀 관리와 대화창 여러 질문 한 번에

**작업 내용**

**작업 목적**
AI를 사람 팀처럼 근무·휴가로 관리하고, 대화창에서 질문과 업무가 섞여도 한 번에 나눠 처리하게 함.

**주요 변경**
- 팀 관리 탭: 근무·휴가 칸 사이로 옮기면 휴가인 AI는 사무실 출입문으로 나가고, 새 배정과 PM 계획에서 빠지며 열린 업무는 대신 맡을 AI에게 넘김.
- 캐릭터 하나 = 계정 하나로 정리함(Studio A = Gemini 키 A, Studio B = 키 B, Codex (Linear) = ChatGPT 계정). 기획에서 ChatGPT를 빼고 Gemini 초안 + Claude PM으로 정함.
- 대화창이 Gemini로 먼저 판단해 질문·업무를 최대 5개로 나누고, 답을 기다리는 중에 보낸 말도 모아서 한 번에 읽음.
- 올리기 승인 전 작업 브랜치 미리보기 push, 프로젝트에서 지켜야 할 것(AI가 적어 쌓음), 새·기존 저장소에 AI 작업 규칙 파일(CLAUDE.md) 넣기를 추가함.
- 다크 모드(밝게·어둡게), 숫자 배지 통일, 작은 창에서도 작은 사무실 등 화면을 다듬음. Gemini 질문 답을 더 빨리 받게 함.

<details><summary>세부 정보 (작업 이유, 확인 결과, 다음 작업)</summary>

**작업 이유**
Grok처럼 무료로 자동 호출할 수 없는 AI를 빼고도 일이 막히지 않게 하고, 쓰지 않는 AI가 업무를 잡고 있지 않게 하려고 휴가 기능을 만듦. 프로젝트마다 반복되는 주의사항을 AI가 스스로 쌓게 함.

**확인 결과**
휴가 전환·업무 넘김 시험, 대화 묶음 처리 시험, DB 규칙 시험이 통과함. 휴대폰·PC 화면에서 탭·빈칸 문제를 스크린샷으로 확인하며 고침.

**다음 작업**
조사 업무를 무료로 처리하고, 결과를 자동으로 채점해 다시 개발을 보내는 흐름이 필요함.

## MinLab AI Office
2026-11-02
v0.4.61 ~ v0.4.97

### 자동 채점·Gemini 개발·토큰 아끼기 규칙과 화면 증거

**작업 내용**

**작업 목적**
개발 결과를 사람이 보기 전에 AI가 먼저 채점해 고칠 점을 돌려보내고, 쉬운 일은 무료 Gemini가 개발하며, 모든 AI 지시서를 짧고 정확하게 만들어 토큰을 아낌.

**주요 변경**
- 조사는 Gemini + Google 검색으로 출처를 붙여 답함. 프로젝트별 대화창, 한 일 기록, 모든 프로젝트 기본 규칙을 추가함.
- 결과 점수 평가: 규칙 검사(토큰 0) → AI 채점(100점) → 80점 미만이면 고칠 점만 적어 자동 재개발(최대 2번). 서로 바꿔 채점(Claude 결과는 Gemini, 나머지는 Claude).
- 난이도 기반 배정(쉬움 Gemini·보통 Codex·어려움 Claude)과 Gemini 개발(GitHub Actions에서 무료 키 A·B로 개발·시험 후 작업 브랜치만 push)을 앱에 연결함.
- 견본은 Studio A·B가 한 장씩 만들고 소유자가 골라 승인함. PM이 계획을 멈추고 물으면 업무 카드에서 답하고 다시 보냄.
- Ponytail·Agent Skills·The Agency에서 고른 개발 습관(가장 작은 변경·보안 규칙·후한 점수 금지)과 저장소 지도를 지시서에 넣음. Gemini 개발이 데스크톱·휴대폰 화면을 찍어 결과에 붙이고, 코드 그래프(Graphify)로 호출부를 찾음. 개발 AI의 shortcut 주석을 "미뤄 둔 일"로 모음.
- 내 차례 바로 가기, 종 아이콘 알림, 첨부 사진 팝업, 확인 질문에 카드에서 바로 답하기 등 휴대폰 사용을 다듬음.

<details><summary>세부 정보 (작업 이유, 확인 결과, 다음 작업)</summary>

**작업 이유**
소유자가 "토큰 아껴야 돼", "그림은 내가 보고 고르기, 코딩 작업은 클로드가 채점"을 요청함. 견본 만들기가 안 된 원인이 PM 질문 미응답이라 답하는 길을 만듦. 외부 플러그인은 보안·적용 범위 때문에 깔지 않고 아이디어만 옮김(헤드룸은 실측 압축 0%라 제외).

**확인 결과**
시험 254개·DB 시험·서버 함수 타입 검사가 통과함. 운영에 DB 규칙 0032~0034와 서버 함수 8개를 배포하고 보조 개발 루틴 안내문에 '채점' 종류를 추가함. Gemini 개발 첫 시험(테스트 저장소 README 한 줄)이 성공함. 화면 촬영 스크립트를 이 앱 빌드로 돌려 콘솔 오류 0·넘침 없음을 확인함. Gemini 개발이 실제 업무에서 스크린샷을 붙이는지는 아직 미확인.

**다음 작업**
쉬운 업무 하나를 Gemini 개발로 돌려 스크린샷·채점이 실제로 이어지는지 확인할 필요가 있음. 무료 API 예비 경로(Groq·Mistral·Cloudflare FLUX)는 키를 받은 뒤 연결함. Gemini 503 과부하 때 다른 모델로 넘기는 처리도 남아 있음.
</details>
