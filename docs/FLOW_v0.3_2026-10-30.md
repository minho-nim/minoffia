# 업무 플로우 v0.3 (소유자 수정, 2026-10-30, Asia/Seoul)

목표: **PC를 모두 끈 상태에서 모바일만으로 개발 요청 → 승인 → Codex 실행 → 결과 확인**까지 할 수 있어야 한다.
구조: 클라우드 웹앱(Cloudflare Pages + Supabase) ↔ 집 PC·회사 PC·모바일 ↔ Supabase 중앙 데이터(프로젝트·AI 세션·대화·승인·개발 결과) ↔ Claude Cloud(PM·업무 분해) / Codex Cloud(실제 코드 개발).

## 12단계

| # | 단계 | 내용(소유자 원문 요약) |
| --- | --- | --- |
| 01 | 사용자 자연어 입력 | 프로젝트를 고르고 자연어로 요청. 이미지·오류 스크린샷·디자인 레퍼런스·URL·파일 첨부. 기존 project_id에 연결하고 원본 자료 저장 |
| 02 | GPT + Gemini 요청 분석 | GPT가 의도·요구사항 분석. 이미지는 Gemini A가 먼저 분석해 GPT에 전달(필요 시 B). URL은 실제 접근 가능한 내용만, 기존/목표 화면 구분. 외부 모델은 필요할 때만, 비공개 소스·인증정보는 검증되지 않은 무료 AI에 주지 않음 |
| 03 | 요청 유형 판별 | 단순 질문 / 오류 수정 / 기존 기능 개선 / 신규 개발. 일반 질문은 GPT가 답하고 종료, 개발 요청만 다음 단계, 모호하면 확인 |
| 04 | GPT 기획 | 추가 질문 후 개발 목표·기능 명세·UI 요구사항·유지 조건·테스트 기준 정리, Claude PM용 지시서 작성 |
| 05 | 사용자 기획 승인(A) | 승인·수정·추가 요청. 승인 전 개발 시작 금지, 승인된 지시서 버전과 원본 첨부 보존 |
| 06 | Claude PM 업무 분해 | 세부 작업·우선순위·의존성·담당 AI. Codex 주 개발, Claude 보조, Gemini 시각 분석·프로토타입, Grok 선택 검토. 모든 AI 자동 호출 금지 |
| 07 | 개발 방식 결정 | Claude가 **Prototype First**(AI Studio Build → 시안 검토 → Codex 통합: 신규 앱·UI 전면 개편·새 인터랙션) 또는 **Direct Development**(Codex 바로: 버그·기존 기능·DB·성능) 제안, 사용자 확인. 프로토타입은 검토 후 소스·시각 자료를 Codex에 인계(자동 불가 시 ZIP) |
| 08 | AI 실행 승인(E) | 실행 승인만 누르면 클라우드 실행 관리자가 Codex Cloud에 작업 생성 요청(목표). 공식 `codex cloud exec` 우선 검증, 연결 안 되면 수동 실행 대기. Claude 안에 Codex CLI 설치 금지 |
| 09 | Codex Cloud 개발 | 구현·통합·버그 수정·테스트. 프로토타입이 있으면 시안의 구성·인터랙션 보존. 실행 ID·결과 관리, 확인 안 된 실행을 진행 중으로 표시 금지 |
| 10 | 결과 검토 | 변경 파일·diff·테스트·스크린샷/미리보기. 수정 요청은 맥락 유지한 채 Claude 재분배. GitHub 업로드 전 산출물 별도 보존 경로 필요(실행 환경별 실측) |
| 11 | GitHub 업로드 승인(B) | 승인 후에만 브랜치·PR·CI. 운영 배포 승인과 별개. 승인 전 자동 푸시·PR 차단 |
| 12 | 운영 배포 승인(C) | 최종 확인 후 승인으로 Cloudflare Pages 배포. 배포 결과 저장, 개발 기록 갱신. 운영 브랜치 자동 배포는 승인 절차와 충돌하지 않게 별도 제어 |

## 남은 결정·확인
- **08 모바일 Codex**: ChatGPT 모바일 앱에서 Codex Cloud 작업을 시작·확인할 수 있는지 소유자 실측.
- **07 Prototype First**: AI Studio Build 결과물을 어떻게 받을지(ZIP 업로드 / GitHub 저장소 / 링크).
- **개발일지**(소유자 결정 2026-10-30):
  - 올릴 곳: 미정. 소유자가 나중에 알려 준다(개발일지 프로젝트는 따로 있음, "MinLab 아카이브"). `minho-nim/MinLab` 저장소 안이라면 '건드리지 않는다' 규칙의 예외를 소유자가 따로 정해야 한다.
  - 형식: 날짜(KST)별로 쌓고 프로젝트 ID를 함께 둔다(개발일지 Markdown의 프로젝트 제목에 `프로젝트 ID`). 파일 배치는 올릴 곳이 정해질 때 정한다.
  - 정리: AI Office가 모은 기록(기획서·계획·결과·PR·배포·업무 대화)을 한 번에 정리한다. 소스 코드는 넣지 않는다. 기본은 Gemini 무료, 깊은 정리만 GPT로 넘김.
  - 올리는 시점: 자동으로 올리지 않는다. 소유자가 입력창에서 "개발일지 업데이트"를 요청 → 미리 보기 확인 → "올려"라고 할 때만.
- GITHUB_REPO_TOKEN에 배포할 저장소의 **Contents: Read and write** 권한 추가(소유자).

### 03 결정(소유자 승인): 질문은 "규칙 → Gemini 한 번 → GPT로 넘기기"
- 앱 상태 질문은 규칙이 바로 답한다(0토큰, 지금과 같음).
- 일반 질문은 보내기 한 번에 Gemini 무료가 답한다(버튼을 따로 누르지 않음, 하루 상한 표시).
- 답 아래에 "GPT에게 이어서 묻기"를 두어, 질문·Gemini 답·맥락을 한 번에 복사한다(모바일 ChatGPT 앱에 붙여넣기).
- 프로젝트와 관련된 질문(코드·기획 판단)은 처음부터 GPT로 넘기도록 안내한다.
- 이렇게 하면 "GPT가 최종 답변자"라는 새 플로우를 지키면서, 가벼운 질문은 무료로 바로 끝난다.
