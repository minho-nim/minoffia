# 현재 업무 흐름

1. 사용자 요청·자료 → 프로젝트 확인 → Gemini 기획서 초안. 앱 상태 질문은 규칙, 일반 질문은 Gemini가 답한다.
2. **기획 승인(A)** → Claude PM 분배·계획 자동 제출. 작은 일은 규칙으로 바로 배정, PM 불가 시 Gemini 대체. PM은 저장소를 읽기만 한다. 확인 질문에 답하면 재계획한다.
3. 견본 먼저(Studio A·B 견본 → 견본 승인 P)는 쓰지 않는다(v0.6.23 소유자 결정 '구조 줄이기', 코드는 남겨 둠). 계획은 늘 바로 개발.
4. **실행 승인(E, 자동)** → 계획이 오면 서버(submit-plan)가 기획 승인에 포함해 실행 승인을 기록하고 담당 AI(Claude·Codex)를 바로 시작한다. 결과가 오면(submit-result) 기다리던 다음 작업도 서버가 시작한다(앱을 닫아 둬도, v0.6.28). 앱이 만든 계획(작은 일 규칙·Gemini 분배)과 서버가 1분 안에 못 한 것은 앱이 이어받는다(소유자 결정 2026-11-10 '승인 3개'). 확인 질문이 남은 계획·견본 승인 전에는 자동으로 하지 않는다. 담당 AI 실행. 개발은 Codex가 주(Linear 위임 또는 Codex 앱에 붙여 넣기), Codex가 휴가면 Claude 보조 개발(루틴). Gemini 개발은 @Gemini로 정할 때만. Codex가 시작하지 못하면(환경 없음·한도) 그 작업을 Claude로 넘긴 새 계획을 만들어 바로 이어서 한다(v0.6.30). 앞 작업이 있으면 그 작업이 끝난 뒤 앱이 시작한다. 모든 AI 작업에 실행 승인 필요.
5. 결과(diff·시험·스크린샷·출처) 수신 → 규칙 검사 → Gemini 무료 채점(기본, 판정·자동 다시 개발은 이 점수로) → 사용자 검토. 소유자가 '교차 채점 추가'를 누르면 다른 AI(Codex 결과 → Claude, Claude 결과 → Codex는 Linear 연결 뒤)가 한 번 더 채점해 평균을 보여 준다(v0.6.26, 판정은 그대로). 자동 수정은 최대 2회 후 사용자에게 넘긴다. Codex도 1회용 제출표로 결과를 직접 보낸다(못 보내면 수동 등록).
6. **올리기 승인(B)** → PR·CI 확인. Claude·Codex 자동 결과는 GitHub Actions(open-pr)가 승인된 diff 그대로 `ai/<도구>/…` 브랜치에 올려 PR을 연다. 대상 저장소에 CI가 없으면 이 저장소의 '대신 검사'(proxy-ci)로 확인한다. 같은 계획의 다른 작업이 진행 중이면 승인 불가. Claude/Gemini는 시험 뒤 작업 브랜치만 미리보기용 push 가능하나 B 전 PR·병합·배포는 금지한다.
7. **배포 승인(C)** → 서버가 CI 통과한 정확한 커밋을 확인해 squash 병합·release fast-forward. main의 추가 변경이 있으면 사용자 확인, CI 진행 중이면 대기한다. 대상 저장소에 release 브랜치가 없으면 main 병합이 곧 배포다. 이 저장소 자체 운영 배포는 별도 소유자 요청 때만 한다.

수정 요청은 기존 맥락으로 재계획하고 새 작업은 실행 승인을 다시 받는다. 승인·버전별 중복 실행은 DB 원자적 예약으로 막는다. 화면과 DB의 승인 조건은 같아야 한다.

대화 화면은 계정에 저장해 기기 간 이어 보며, 개발일지용 대화는 프로젝트·업무 메시지만 남긴다. 실제 운영 검증 범위는 [현재 상태](STATUS.md), 당시 결정 근거는 [보관 안내](archive/README.md) 참조.

두 AI 비교(v0.6.54): 작업 하나짜리 업무의 결과가 오면 소유자가 '다른 AI로도 해 보기'를 누를 수 있다. 같은 작업을 다른 AI(Codex↔Claude)에게 새 계획으로 따로 맡기고(실행 승인은 기획 승인에 포함), 두 결과를 각각 채점한다. 올리기 승인은 늘 최신 결과만 받으므로, 이전 결과를 고르면 같은 변경을 새 버전으로 다시 저장한다.

스킬(v0.6.55): 스킬 탭에서 이 저장소 스킬을 본다(GitHub 읽기만). 만들기·찾기는 minoffia 프로젝트의 보통 업무로 접수하고(@Claude), 결과는 채점·올리기 승인·PR을 거쳐 .claude/skills에 들어온다. 외부 스킬 설치도 이 올리기 승인이 소유자 승인이다.
